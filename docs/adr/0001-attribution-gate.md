# ADR-0001：归因必须过闸门

- 状态：后端闸门已实现（workbench 动作 + 生成前拒绝），界面入口待接入
- 日期：2026-11-11
- 相关：ADR-0002、ADR-0003

## 背景

一本 170 章的小说里有 1,390 条对白。用正则和叙述动词猜测说话人，实测**约 40% 判错**，
而且错误不是随机的——两人对话场景里会系统性反向：叙述说某人"反应"，抽取器就把这句判给他。
听众不会说"归因错了"，他们说的是"这个人的声音一直在变""他一个老头子怎么听起来像姑娘"。

三种错误最贵：

1. 七十岁的政府 Saint 用了年轻主角的音色（缺角色，落到兜底音色）
2. 两人长对话整段反号，90% 的句子被翻转
3. 引号内外的长句被判成旁白，本该由角色说的话由旁白读了

正则提出的修正方案人工核对后**三次只对一次**：一次把「对 Saint Madoc 说话」改成了「由 Saint
Madoc 说」。所以正则只能提议，决定必须由读过正文的人做出。

## 决策

渲染前强制经过一个四态闸门，状态记在章节上：

```
pending → read → attributed → verified
```

- `read`：该章正文被 dump 过，并对正文取 sha256（换文库或改正文会让状态失效）
- `attributed`：为**这段确切正文**记录过说话人映射
- `verified`：带着归因重新通读一遍并确认
- **任何渲染入口在章节低于 `verified` 时拒绝执行**，报错要指出是哪一章、缺哪一步

改写走覆盖表，键为 `章节:段落下标`，支持三种动作：

```json
{
  "1097:37": "sunny",
  "1071:3":  {"speaker": "nephis", "kind": "dialogue"},
  "1077:36": {"speaker": "narrator", "kind": "narration"}
}
```

裸字符串只换说话人；对象可以**改 kind**——把被吞掉的旁白提升成对白，或把误判的对白降回旁白。

## 依据

- `ss_audiobook/attribution_gate.py`：170 章全部 verified 后才允许 `build`
- `~/.pi/skills/breeze-audiobook/references/attribution.md`（40% 判错率、8 类错误、1/3 命中率）
- 本卷数据：`data/attribution_state.json` 中 170 章均为 `verified`，且每章带 `text_sha`

## 后果

- 界面必须能展示闸门状态、能"我读完了"地确认一章，并在批量渲染上拦住未确认的章节
- 正文一变（重新导入 epub、改字号不算）就回到 `pending`，避免用旧归因渲染新文本
- 代价是每章至少两遍人工通读；换来的是不会白烧 GPU 渲染一本观众听不下去的书

## 备选方案

- **只信模型自动归因**：省人力，但 40% 错误率下整本书不可听
- **按置信度阈值自动放行**：0.7 的阈值下仍有大量反向错误通过了阈值，阈值不能代替阅读
- **把闸门做在脚本里**（现状）：有效，但只有跑脚本的人受约束；界面里点一下就能绕过
