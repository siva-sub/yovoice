# ADR-0012：书是一层对象，不是 170 个互不相干的作品

- 状态：已采纳，待实现
- 日期：2026-11-11
- 相关：ADR-0001、ADR-0003、ADR-0006、ADR-0011
- 覆盖的候选特性：书级仪表盘、系列复用、说话人覆盖矩阵、章缝连续性、cast-wide 漂移时间线、全局异常复核

## 背景

导入一本 170 章的小说，`book-import.tsx` 会产出 170 个彼此独立的作品（`bookDrafts`）。
全仓库没有 `bookId` / `seriesId` 之类的容器。这带来三个具体后果：

1. **没有进度**：想知道"还剩多少章没复核、多少章没渲染"，只能靠数文件。
2. **没有一致性检查**：哪些角色在哪几章说过话、某个角色是不是整卷只出现一次（那是误判的
   强信号）、同一角色在第 80 章与第 81 章之间音色是否变了——都无从问起。
3. **没有复用**：同一系列的第七卷要重新建角色表、重新设计音色、重新定音效策略，
   而唯一变的是新增角色。

真正的作业单位是"一本书（一卷）"，不是"一章"。这一层缺了，上面所有跨章能力都无处依附。

## 决策

引入 `Book`（卷）作为容器，章节作品是它的成员：

```text
Series（系列，可选）  ── 复用：cast 谱系、音色锚点、风格与音效策略
  └─ Book（卷）        ── 拥有：书名、章序、闸门进度、渲染清单、响度标准
       └─ Work（章）   ── 拥有：cue、take、混音
```

`Book` 只存**归属与策略**，不复制章节内容：

- `title`、`seriesId?`、`order`（卷序）
- `castPolicy`：默认模型、默认 `guidance`、逐句指令的启用条件
- `sfxPolicy`：四层的默认电平与密度（ADR-0004）
- `loudnessTarget`：导出标准（默认 −19 LUFS，峰值 ≤ −3 dBTP）
- 章序就是物理顺序，不做额外排序

四类跨章视图由它派生，全部是**只读派生数据**，不落新状态：

| 视图 | 回答的问题 |
| --- | --- |
| **进度矩阵** | 每章在 imported → read → attributed → verified → rendered → qa → mixed → shipped 的哪一格；下一件事是什么 |
| **说话人覆盖矩阵** | 角色 × 章节的台词分布；谁被提到却零台词、谁整卷只出现一次 |
| **章缝连续性** | 第 N 章末句与第 N+1 章首句的同一角色音色余弦；渲染分块导致的边界跳变会在这里露出来 |
| **cast-wide 漂移时间线** | 每个角色的音色余弦随章节号的变化，用来指出"从第几章开始漂" |

## 依据

- `book-import.tsx` 只产出作品，全仓库无书/卷标识
- 本卷实测：170 章 / 22 小时是**分块渲染**的（不同 GPU、不同会话），章缝是最可能出现音色跳变的
  位置，但现在没有任何检查点
- `voice_bible_v5.json` 与 `data/places.json` 本身就是"整卷一份"的策略对象，说明用户的
  心智模型早就是书级而不是章级

## 后果

- store 需要一次迁移：新增 `Book` 表与作品的归属字段，旧作品落进一个"未归档"默认卷
- 派生视图要能在大书上跑得动（170 章 / 8,970 cue），所以聚合在读取时算、缓存在内存，
  不写入库
- 系列复用只复用**策略与角色谱系**，不复用正文与锚点音频本身（卷与卷是独立的书）
- 引入书之后，"确认读过"这类动作仍以章为单位（ADR-0001），书级只是汇总，不能批量盖章

## 备选方案

- **用作品标题前缀假装成书**（例如 `Vol6/ch1061`）：能凑合排序，无法承载策略，也无法做覆盖矩阵
- **每个系列单独一个数据目录**：隔离得干净，但切卷要重启应用，且跨卷统计（同一角色的漂移）
  做不了
