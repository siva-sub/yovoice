# ADR-0013：验收对象是音频，不是文本

- 状态：部分实现：QARecord/RecordQA/ChapterProgress 与单章验收脚本已落地；回读 WER 自动接线与通听界面待实现
- 日期：2026-11-11
- 相关：ADR-0001、ADR-0009、ADR-0012
- 覆盖的候选特性：校对式通听、渲染回读与脚本比对（WER 闸门）、逐章响度报告、静默/空洞检测

## 背景

现有闸门只保证"文本是对的"（ADR-0001）。但它管不到音频：模型可能吞词、读错人名、
把一条 take 渲成了别人的音色，或者两句之间留下 4 秒空洞。这些只能**听**出来，
而听完 22 小时不现实。

工具链其实已经具备条件：仓库里有转写页与逐字对齐（Qwen3 ASR 0.6B + Forced Aligner），
渲染时也知道每一条 cue 对应哪段音频。**把两端接起来，就能在不听的情况下抓出大部分音频缺陷。**

## 决策

验收分四件事，全部以章为单位产出可判定的结果：

1. **渲染回读（WER 闸门）**：对渲染好的章做转写，与 build 时的 cue 文本按词比对。
   词错误率超过阈值（默认 5%）即判失败，并列出**具体是哪些词**错了——读错人名、吞词、
   多出字都在这里显形。这是唯一能自动发现"模型念错了名字"的手段。
2. **逐章响度报告**：LUFS 与真峰值（true peak）按目标比较（默认 −19 LUFS，≤ −3 dBTP），
   超限不许导出。industry 标准按平台，阈值可配置。
3. **空洞与静默检测**：章内超过 1.5 s 的静音、整章静音、削波。静音常常意味着一条 take 失败
   但没报错，属于最容易被漏掉的一类缺陷。
4. **校对式通听**：按章顺序播放，任意位置可标记问题（`M` 键），标记落在**最近的 cue** 上，
   形成"cue 级待办"。一章听完才能盖章 `qa`。标记不走归因改派（ADR-0007），走独立的缺陷队列。

验收结果记在章上（`qa: {wer, lufs, peak, silences, verdict, at}`），书级进度矩阵（ADR-0012）
据此推进到 `qa` / `mixed`。

## 依据

- 仓库已有转写与强制对齐（`features/transcribe/`、`qwen3-asr-0.6b` + aligner）
- 第三方基准显示 Breeze 的 WER 为 **0.109**（对比 Qwen3-TTS 的 0.058），说明"吞词/读错"
  在这个模型上是真实存在的失败模式，不是假想
- 本卷实测：渲染分块在不同 GPU 会话上完成，空洞与边界跳变是最可能的实际缺陷类型

## 后果

- 回读需要一次额外的转写推理（每章），可以放在音效车道等空闲卡上跑，不占人声车道
- WER 阈值不能一刀切：专有名词多的小说天然偏高，所以要看**错的是哪些词**而不是只看数字
- 通听模式是"人可以离开几分钟"的交互，必须能中断、能续听（记住听到哪）
- 响度标准按平台不同，默认值写进 `Book.loudnessTarget`，不硬编码

## 备选方案

- **只做人工通听**（现状）：最准，但 22 小时一遍，改一句就要再听一遍
- **只信自动指标不上人耳**：WER 抓不到韵律、情绪与"读对了但语气不对"，所以最后仍要通听，
  只是把"找缺陷"换成"确认没有缺陷"
