# ADR-0007：归因阅读与改派是一等界面

- 状态：已采纳，待实现
- 日期：2026-11-11
- 相关：ADR-0001、ADR-0002、ADR-0004
- 覆盖的候选特性：#1 键盘复核、#3 两人对话翻转探测、#6 章节差异、#7 提词器试听

## 背景

整套流程里唯一无法自动化的环节是"读一遍并决定谁在说话"。脚本时代它长这样：

```text
##### CHAPTER 1097 #####
[ 34] ~ The old man shifted his gaze, subjecting Sunny to a piercing stare.
[ 35] <sunny|0.62|lead_next> "What about you, young man?"
[ 36] ~ Sunny shifted uncomfortably, suspecting that there was a hidden meaning.
[ 37] <cor|0.62|lead_next> "I feel like it's a good fit for my abilities."
```

紧凑、可读、能一次装进上下文 8–15 章。现有界面能改每行的说话人，但**读起来不如上面这段**：
每行被拆在单独的输入框里、判断依据不可见、没有"下一处可疑"的推进方式。要人读 8,970 行，
界面必须为"读"优化，而不是为"编辑"优化。

## 决策

归因页以**阅读**为主视图，编辑随处可达：

1. **一行一句，四栏固定宽度**：序号、类型标记（`~` 叙述 / `"` 对白 / `·` 心声）、说话人、
   正文。正文最多两行，超出折叠，点击展开。整章默认一屏读完。
2. **判断依据就在行尾**：`<sunny 0.62 lead_next>` 这样的紧凑标记，鼠标悬停给出人话解释。
   低于 0.5 的行整行加左侧色条——扫一眼就知道有几处要看。
3. **改派是单键操作**：数字键 1–9 对应本章出现过的说话人（顺序固定，不随选择变化），
   `0` 设为旁白。改动即写入，无确认弹窗；`Ctrl+Z` 撤销。
4. **复核队列**：`J/K` 跳到上/下一处可疑（`confidence < 0.5`），`A` 接受、`F` 标为待讨论。
   队列是本章内有序的，不跨章合并。
5. **两人对话翻转探测**（只提议）：同一段的问句与答句归给同一人、或交替模式与叙述相反时，
   在章首列出提议条数与位置。**永不自动应用**——实测这类提议三次只对一次，且会把"对某人
   说"改成"由某人说"。
6. **差异视图**：闸门按正文 sha 记状态（ADR-0001）。一章重新导入后，只展示变化的句子，
   并把受影响的行重置为待复核，未变化的行保留原决定。
7. **提词器试听**：按顺序播放本章 cue，屏幕上高亮当前行与说话人名。有些错误听一遍就出来了，
   比再读一遍快。

## 后果

- 单章正文上限 11,000 字符（前端 `partTextLimit`），阅读视图必须能处理拆段后的"第 3/5 段"
- 键盘映射要跟着说话人集合变化而重排，所以映射在进入章节时固定一次，中途不重排
- 撤销栈按章节持有，不跨章；离开章节时丢弃并提示
- 所有这些只改 `speakerId` / `kind`，不碰正文，因此不会改变闸门的 `textSha`

## 备选方案

- **只在编辑器里加一列说话人**（现状）：能改，但读起来慢，实际上会退化成"挑几行看看"
- **导出成文本、外部编辑再导回**：脚本时代就是这样，可行但没有依据标记与快捷键，且容易漏章
