# ADR-0014：多书与系列的作用域

- 状态：已采纳，待实现
- 日期：2026-11-11
- 相关：ADR-0012、ADR-0006、ADR-0010、ADR-0011
- 覆盖的候选特性：书架与书切换、系列复用、跨书队列与配额、共享资产引用计数、归档

## 背景

现实里有三件事同时成立：

1. **同一系列有多卷**。第六卷与第七卷是同一个世界的延续，Jon 的 Sunny 与第七卷的 Sunny
   是同一个人，音色必须一致；重新设计一遍是纯浪费。
2. **不同系列会重名**。另一本小说里也可能有叫 Sunny 的角色，但那是另一个人、另一种音色。
   同名不等于同一个人。
3. **一台机器只有一张卡**。多条书的工作要排队共用引擎，而某一卷不能把另一卷饿死。

存储层还有个必须正视的事实：状态是**单个 SQLite**（`yovoice.db`），一张表对应 `State` 的一个
字段，每行一个实体；打开时**整个 State 读进内存**，每次提交把内存快照与上次比较、只写变化的行。
于是**单次保存的代价随总库大小增长，而不是随改动大小增长**。

## 决策

### 作用域

| 实体 | 作用域 | 理由 |
| --- | --- | --- |
| Series | 全局 | 系列是复用的单位 |
| Book | 属于一个 Series（也可独立） | 一卷一本 |
| **角色（cast）** | **Series 级，可按 Book 覆盖** | 同系列的 Sunny 是同一人；别部的 Sunny 是别人 |
| **锚点音频（Voice）** | **全局、内容寻址** | 同一音色跨卷共用，文件只存一份 |
| 音色策略（design / f0 / seed） | Series 级，可按 Book 覆盖 | 换模型时整系列一起改，允许某卷单独试验 |
| 音效 cue 库与地点表 | Series 级 | 地点属于世界观（链岛、南极） |
| 响度与导出预设 | Book 级 | 平台与卷可能不同 |
| 渲染队列 | **跨书统一，按书分配配额** | 一张卡服务所有书 |
| 复核包 | Book 级 | 范围与版权边界 |

### 同名规则

- **同名不同系列 → 两个独立角色**，各自锚点
- **同名同系列 → 同一角色**（合并是意图，不是意外）
- 新建书时若已存在同名角色，界面必须显式问"复用 / 新建"，不许静默选一个

### 工作方式

1. **书架是入口**：按系列分组，每本显示进度汇总（ADR-0012 的矩阵）与"下一件事"。
2. **一次只有一本 active book**：归因页、角色页、音频库、混音都跟着它；**切换不重载模型**，
   引擎与书无关。
3. **跨书队列**：可以排多本书的批量，配额按书分配（例如 60/40），"正在听的那本"优先；
   音效与配乐等填缝工作跨书共用一个低优先车道。
4. **共享资产引用计数**：删除一本书不删锚点音频，除非没有别的书/系列引用它。
5. **归档**：`shipped` 的书可归档为只读——从队列排除、不再计入校验，但可检索与导出。

## 规模上限（要量，不要猜）

快照式提交意味着单次保存要遍历全部实体。当前一卷 170 章 / 8,970 cue 是可接受的；
**3 本书约 510 个作品实体，20 本约 3,400 个**——后者需要先量一次保存耗时与内存占用再决定。
若真的到瓶颈，逃生口是把章节正文改为按需加载（cue 与策略仍常驻），而不是分库。
在测量之前不预先实现懒加载。

## 依据

- `internal/store/db.go`：`snapshot` + 每字段一张表 + 只写变化行；`decode` 一次性填满 `State`
- `internal/store/cleanup_previous.go`：数据目录里 `voices/`、`outputs/` 与库同级，
  因此锚点音频天然是全局文件，适合内容寻址复用
- 用户实际使用：第六卷与第七卷是同系列两卷；`voice_bible_v5.json` 与 `data/places.json`
  都是"整卷一份"的策略对象

## 后果

- 迁移：现有 170 个作品归入"Shadow Slave 第六卷"，挂在"Shadow Slave"系列下；旧的无主作品
  进"未归档"默认卷
- 缓存键：章节级 take 含 `bookId`；**锚点按内容寻址，不含 bookId**，所以换卷照样命中
- 删除路径要检查引用计数，避免删书时连带删掉别的卷在用的锚点
- 归档书仍占磁盘；归档时应提示可导出的交付物（m4b、试听包）与可清理的大文件

## 备选方案

- **每本书一个数据目录**：隔离最干净，但切换要重启、跨卷统计（同一角色跨卷漂移）做不了，
  且共享锚点无法复用
- **全局单一 cast**：跨卷复用最省事，但同名不同系列会直接串音，属于静默的严重错误
- **每卷独立 cast，不共享**：不会串音，但第七卷要把 18 个角色与 21 条锚点重做一遍
