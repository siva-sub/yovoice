# ADR-0010：渲染前先算成本，缓存优先，可续跑

- 状态：成本预估脚本已交付（`analyze.py cost`），预算闸门、缓存与续跑待实现
- 日期：2026-11-11
- 相关：ADR-0003、ADR-0005
- 覆盖的候选特性：#8 成本预估与预算闸门、#9 缓存命中面板、#10 可续跑清单、#11 热车道保活、#12 分车道队列

## 背景

一本书 1,317 分钟音频。同一个工作，模型选错就是 **45.7 GPU 小时** vs **3.3 GPU 小时**（ADR-0003）；
Colab 账号当时结余 265 计算单元。也就是说，"能不能渲染完"在按下开始之前就已经决定，
而现有界面里没有任何一处会告诉用户这件事。

另外两个已知损失：冷启动比热启动慢 **14 倍**（Qwen3-TTS 1.7B 实测 0.25× vs 3.58×），
而 Colab 会话会被回收——跑到一半断掉，如果没有清单就得从头再来。

## 决策

渲染入口先算账，再排队：

1. **成本预估**：`字数 / 模型 RTF` 得到 GPU 小时，再按卡型折算计算单元，显示"预计 N 小时 /
   M 单元，当前结余 X"。数字来自已渲染数据反推的 RTF，不是手册值。
2. **预算闸门**：预计超过结余时**拒绝开始**并给出三个可选动作：换模型、只渲某几章、
   先渲低置信度已复核的章节。允许显式覆盖，但要留记录。
3. **缓存命中面板**：按 `hash(modelId, anchorRev, text, instruction, cfg, seed)` 判断命中；
   面板显示"本次 N 条中 M 条已存在，新增 K 条"。命中即不发请求。音效沿用
   `hash(prompt, seconds, seed)`。
4. **可续跑清单**：每次批量渲染写 `render-manifest.json`（works、cue、take、已完成/待做、
   引擎版本、模型）。会话断掉后按清单续跑，已完成的 take 不重做。
5. **热车道保活**：一条车道常驻一个 `colab new --keep` 会话；界面显示车道状态
   （空闲/忙碌/已断开），断开时尝试重新附着而不是重新租卡。
6. **分车道队列**：人声、音效、配乐各一条队列，可同时占用不同卡型
   （A100 / T4 / L4）。音效与配乐是填缝工作，人声队列在跑时它们不该等。

## 后果

- 成本预估依赖 RTF 数据，所以首次运行是"按模型基准的估计"，跑过一次后改写为实测值
- 拒绝开始是反直觉的交互，必须给出替代方案而不是只报错
- 清单里的引擎版本要参与缓存键：换了 audio.cpp 或模型文件，缓存就必须失效
- 热车道意味着界面需要"我连的是哪台远端"的显式状态，不能假装它是本地引擎

## 备选方案

- **只给一个进度条**（现状）：进度不回答"这要花多少钱"，用户会在 40% 处才发现不够
- **按章平均耗时外推**：章长度差异大（最大 11,301 字符），字数 × RTF 更准
