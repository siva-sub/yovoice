# ADR-0008：角色卡与别名图是cast 管理的中心

- 状态：别名与亲属图提议脚本已交付（`alias-graph.py`），角色页与 store 迁移待实现
- 日期：2026-11-11
- 相关：ADR-0003、ADR-0006、ADR-0007
- 覆盖的候选特性：#2 锚点候选对比、#4 别名与亲属图、#5 未知专名清单、#13 漂移监控

## 背景

整卷 18 个说话人，来自对白的称呼却远多于 18 个：`Sunny / Sunless / Lost from Light /
Mongrel / Devil of Antarctica` 是同一个人；`Saint` 既是阶级又是角色；`brother` 可能是
Mordret 也可能是任何一位同门。会话里为这几件事来回纠正了多次：Morgan 与 Mordret 是两个人、
Rain 是 Sunny 的妹妹、Nephis 被 Valor 家收养因此是 Morgan 的妹妹、cohort / Fire Keepers / kai /
effie / cassie 各有各的关系。

现在这些知识散在正文里靠人记。界面只有一条 `sourceName → characterId` 的映射，无法表达
别名、亲属、以及"这个词取决于上下文"。

## 决策

角色页由四块组成，按信息密度排：

1. **角色卡**：名字、性别、年龄段、`design` 文本、锚点音频、逐字稿、`f0_hz`、`seed`、
   冻结状态与审计结果（ADR-0006 的五个数）。
2. **锚点候选对比**：同一 `design` 渲染 3 个 seed，并排显示五个数与试听按钮，选中一个冻结。
   冻结后其余候选保留为历史，便于换模型时对比（ADR-0003）。
3. **别名与亲属图**：
   - 别名合并：一个角色可有多个称呼，最长别名优先匹配（`Soul Reaper` 胜过 `Reaper`）。
   - 关系边：`brother / sister / father / adopted-by` 等，用于推断"这位兄弟说的是谁"。
   - 歧义标记：`Saint` 这类词单独标记为"阶级或角色"，匹配时按上下文提示而不是直接归人。
   - 图是**提议来源**，不是自动改派来源：它给出候选，人在归因页确认。
4. **未知专名清单**：本章出现但不在角色表里的专有名词，按出现次数排序。这是"七十岁的政府
   Saint 听起来像姑娘"的根因——缺角色时会静默落到兜底音色，所以必须显式列出来。
5. **漂移监控**：定期把新渲染的行与冻结锚点做音色余弦（对数谱），低于阈值时在角色卡上告警，
   并指出从第几章开始漂。这是听众实际会投诉的失败模式，现在只能靠听完 22 小时发现。

## 后果

- 角色表从"扁平映射"升级为"角色 + 别名 + 关系边"，store 需要一次迁移
- 别名与关系是**数据**，不是逻辑：写进库里，界面可编辑，导出时可带走
- 未知专名需要分词与大小写判断（英文人名靠大写与重复出现；`Sunny` 与 `sunny` 要区分）
- 漂移监控依赖已渲染音频，所以它属于渲染后检查，不阻塞渲染

## 备选方案

- **只做 `sourceName → characterId`**（现状）：够用一次，换个文库就要再教一遍
- **让模型读全文自动建角色表**：可以做提议，但关系类判断在这套会话里已经被证明容易出错，
  最终仍需人工确认；把它当唯一来源会让错误沉到 170 章里
